# 03. プロトコル

client と bridge が SSH の標準入出力の上で交わすフレームを定める。実装は `src/protocol.rs`。

---

## 1. 方針

- SSH の標準入出力は、メッセージの境界を持たないバイトストリームとして扱う。
  **1 回の read で 1 メッセージが揃うとは仮定しない。**
- SSH が順序と完全性を保証するので、**再送・順序番号・チェックサムは持たない**。
- 録音セッションの取り違えは、セッション番号で防ぐ。
- 確認応答（ACK）の類は置かない（決定）。START に対する返事は、音声の開始（`AudioBegin`）か
  断り（`AudioEnd`）で足りる。

## 2. フレーム

```
+------+-------------+---------+
| type | length (LE) | payload |
|  u8  |     u32     |  bytes  |
+------+-------------+---------+
```

- 整数はすべてリトルエンディアン。
- **payload は 64 KiB まで**（`MAX_PAYLOAD`）。これを超える長さは、確保する前にエラーにする。
- 知らない type、型に対して短すぎる payload は、エラーとして接続を終える。

## 3. メッセージ

| type | 名前 | 向き | payload | 意味 |
|---|---|---|---|---|
| 1 | `Hello` | client → bridge | magic `MMUX` + version (u16) | 最初に必ず送る |
| 2 | `HelloAck` | bridge → client | magic `MMUX` + version (u16) + source 名 (UTF-8) | 仮想マイクの用意ができた |
| 3 | `Start` | bridge → client | session (u32) | 録音要求が発生した |
| 4 | `Stop` | bridge → client | session (u32) | 録音要求が無くなった |
| 5 | `AudioBegin` | client → bridge | session (u32) + rate (u32) + channels (u8) | これから送る PCM の形式 |
| 6 | `Audio` | client → bridge | session (u32) + PCM (s16le) | 音声 |
| 7 | `AudioEnd` | client → bridge | session (u32) + reason (u8) | このセッションの音声は終わり、または送らない |
| 8 | `Ping` | 双方向 | nonce (u64) | 疎通確認 |
| 9 | `Pong` | 双方向 | nonce (u64) | Ping への返事 |
| 10 | `Error` | 双方向 | メッセージ (UTF-8) | 続行できないエラー |

- プロトコルのバージョンは **1**。`Hello` と `HelloAck` で一致を確かめ、違えば接続を終える。
- magic が合わないときは、接続先のログインシェルの出力などが標準出力に混ざっている可能性が高い。
  エラーメッセージでそれを案内する。

`AudioEnd` の reason:

| 値 | 名前 | 意味 |
|---|---|---|
| 0 | `STOPPED` | 取得を止めた（要求の終了・disarm・時間上限のいずれでも） |
| 1 | `DENIED` | armed でないので送らない |
| 4 | `CAPTURE_ERROR` | マイクを取得できなかった |

## 4. 録音セッションの流れ

```
client                          bridge                      アプリ
  │ ── Hello ──────────────────▶ │                             │
  │ ◀───────────────── HelloAck ─│  （仮想マイクを用意）          │
  │            待機（10 秒ごとに Ping / Pong）                   │
  │                              │ ◀──── 録音ストリームを開く ────│
  │ ◀──────────── Start(s) ──────│                             │
  │  （armed ならマイクを開く）    │                             │
  │ ── AudioBegin(s, 16000, 1) ─▶│  （pacat を起動）             │
  │ ── Audio(s, PCM) ───────────▶│ ── PCM ───────────────────▶ │
  │ ── Audio(s, PCM) ───────────▶│ ── PCM ───────────────────▶ │
  │                              │ ◀──── 録音ストリームを閉じる ──│
  │ ◀───────────── Stop(s) ──────│  （300 ms 待ってから）         │
  │  （マイクを閉じる）            │                             │
  │ ── AudioEnd(s, STOPPED) ───▶ │  （pacat を止める）           │
```

- **セッション番号は bridge が振る**。START のたびに 1 ずつ増える。
- **bridge は、現在のセッション宛てでない `AudioBegin` と `Audio` を捨てる**。終わったセッションの残りが、
  次のセッションに混ざらないようにするため。
- disarmed のときは、`Start` に対して `AudioEnd(DENIED)` だけを返す。
- 音声の形式は、接続元が決めて `AudioBegin` で伝える。bridge が受け付けるのは、8,000〜192,000 Hz、
  1〜2 チャンネル。実際に送るのは 16 kHz のモノラルが基本である（[04](./04-audio.md) §4）。
- 1 フレームの音声は 20 ms ぶん（16 kHz なら 640 バイト）。

## 5. 接続先を信頼しない前提での扱い

client は、bridge から届くものを無条件には信頼しない（[05](./05-security.md) §3.2）。

- 想定外のメッセージは、**種類と長さだけ**をログに書く。中身は書かない。
- `HelloAck` の source 名と `Error` のメッセージは、制御文字を取り除き、300 文字で切ってから表示する。
- bridge から届いてメインがまだ受け取っていないメッセージは、64 件までに制限する。

## 6. 未確定・gap

- バージョンの不一致は、接続を終えるだけである。古い版との互換を保つ仕組み（機能の交渉など）は無い。
  いまのところ、バージョン 1 のまま、意味を変えない範囲で実装を変えてきた（録音中の Ping の追加など）。
