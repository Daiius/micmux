# 06. 運用

セットアップ、設定、日々の操作、うまく動かないときの調べ方をまとめる。
利用者向けの手順は `README.md`（英語）と `README.ja.md`（日本語）にもある。ここでは、仕様として何を提供するかを定める。

プログラムとスクリプトの出力（`--help`・エラー・ログ・`doctor` / `debug` の表示）は英語だけにし、多言語化はしない。
コード中のコメント・コミットメッセージ・PRD・issue は日本語で書く（[決定ログ](./_grilling/decisions.md)）。

---

## 1. セットアップ

### 1.1 接続先

必要なものは 3 つ。

| 必要なもの | Debian でのパッケージ | 用途 |
|---|---|---|
| ユーザー権限で動く音声サーバー | `pulseaudio` | 仮想マイクの置き場所 |
| `pactl` / `pacat` | `pulseaudio-utils` | bridge が使う |
| ALSA から音声サーバーへ繋ぐプラグイン | `libasound2-plugins` | ALSA で録音するアプリ（Claude Code）に要る |

`scripts/setup-debian-server.sh` がこれを入れる。

- `--check`: 何も変更せず、現状だけ表示する。
- 引数なし: 不足しているパッケージを確認のうえ入れ、音声サーバーをソケット起動で有効にする。
- `--remove`: このスクリプトが入れたパッケージを取り除く。実際に消えるものを全部表示してから確認する。
- 何度実行しても同じ結果になる。PipeWire が動いている環境では、PulseAudio を入れない。
- `sudo` に渡すのは、スクリプトが持っている固定のパッケージ名だけにする。記録ファイルの内容を
  そのまま引数にしない。

**利用者に実行してもらう手順は、コマンドを並べずにスクリプトにする**（決定）。`sudo` を伴う操作に、
現状の表示・実行前の確認・冪等性・取り除く手順をまとめて持たせるため。

micmux 本体は `cargo install --path .` で入れる。接続先のビルドに、音声関係の開発ヘッダは要らない。
`micmux doctor` で、アプリが仮想マイクに辿り着ける状態かを点検できる。

### 1.2 接続元

`cargo install --path .` で入れる。macOS では、初回の録音時に、ターミナルアプリに対するマイクの
アクセス許可を OS が尋ねる。

- マイクの許可は、起動元のターミナルアプリに対して与えられる。`--background` で端末から切り離しても
  引き継がれる（実測で確認。端末から直接の場合と同じ音量が取れた）。
- Linux を接続元にして内蔵の取得を使う場合は、`--features native` でビルドする（`libasound2-dev` が要る）。

## 2. 設定

micmux 自身の設定ファイルは持たない。接続に関する設定は `~/.ssh/config` に、micmux の動作は
コマンドラインのオプションに書く。

### 2.1 `micmux connect` のオプション

| オプション | 意味 | 既定 |
|---|---|---|
| `--armed` | 最初から録音を許可する | 許可しない |
| `--max-seconds <n>` | 連続録音時間の上限。達すると disarm する。`0` で上限なし | 120 |
| `--set-default` | 接続中だけ、仮想マイクを接続先の既定の録音デバイスにする | しない |
| `--sink-name <name>` | 仮想マイクの名前 | `micmux` |
| `--remote-cmd <path>` | 接続先での micmux の呼び出し方 | `micmux` |
| `--ssh-arg <arg>` | ssh に渡す追加の引数（複数回指定できる） | なし |
| `--transport <cmd>` | ssh の代わりに使う接続コマンド | なし |
| `--capture-cmd <cmd>` | マイクの取得を外部コマンドに任せる | 内蔵の取得 |
| `--capture-rate <hz>` | `--capture-cmd` の出力のレート | 16000 |
| `--background` | 端末から切り離して裏で動く | 前面で動く |
| `--watch-pid <pid>` | 指定したプロセスが終わったら自分も終わる | なし |
| `--mux` | 端末用の SSH 接続に相乗りする | 別の接続を張る |
| `--log <path>` | `--background` のときのログの出力先 | `~/.local/state/micmux/client.log` |
| `--no-bell` | 録音要求を断ったときにベルを鳴らさない | 鳴らす |

- **`--remote-cmd` が要る場面**: 非対話の SSH では、ログインシェルの設定が読まれず、`~/.cargo/bin` が
  PATH に入らないことがある。その場合は `--remote-cmd '~/.cargo/bin/micmux'` と指定する。
- `micmux debug` にも、`connect` と同じ `--remote-cmd` / `--capture-cmd` / `--capture-rate` を付ける。

### 2.2 `~/.ssh/config`

起動の仕方ごとの設定例は [02](./02-architecture.md) §4 にある。

- Host の別名・ユーザー・鍵・踏み台は、普段の設定がそのまま効く。
- micmux が付けるオプション（PTY を割り当てない、多重化しない、など）を config に書く必要は無い。
  コマンドラインの指定が config より優先される。
- `Match originalhost <名前>` は、コマンドラインで指定した名前が一致したときだけ発動する。
  IP アドレスや別の名前で接続すると、micmux は起動しない。
- 自動で起動する設定は、`git` や `scp` がそのホストへ繋ぐときにも発動する。その場合 micmux は、
  接続が終わるのと同時に終わる。
- `--background` では端末が無いので、パスフレーズを尋ねられると失敗する。鍵は ssh-agent に載せておく。

## 3. 操作

動いている client に、別のプロセスから操作用ソケットで指示を送る。

| コマンド | 動作 |
|---|---|
| `micmux arm` | 録音を許可する。要求が続いていれば、その場で録音が始まる |
| `micmux disarm` | 許可を取り消す。録音中なら止める |
| `micmux toggle` | 切り替える |
| `micmux status [--json]` | 状態を表示する |

- **接続元で実行する。** SSH で入った先で打っても、何も起きない。
- client が動いていないときは、「micmux connect is not running」と失敗する。arm の状態は client が
  持つので、`micmux connect` を起動する前に arm しておくことはできない（最初から許可するには `--armed`）。
- client が起動していれば、接続の確立前（多重化のマスター待ち・ハンドシェイク中）でも受け付ける
  （[02](./02-architecture.md) §4.4）。操作用ソケットを開けなかった場合は、受け付けられない。
- `status` の項目: `host`・`armed`・`requested`・`recording`・`sessions`（録音した回数）・`rtt`（往復時間）。
  接続の確立前は、接続待ちであることを示す。
- `toggle` をホットキーに割り当てると、端末を切り替えずに許可を切り替えられる。

## 4. ログ

`--background` で動かしているあいだの表示は、ログファイルに出る。

- 場所は `$XDG_STATE_HOME/micmux/client.log`、無ければ `~/.local/state/micmux/client.log`。
- ファイルは 0600、ディレクトリは 0700。起動時に 1 MB を超えていたら、`client.log.1` へ 1 世代だけ退避する。
- client の行には時刻が付く。bridge の行（ssh の標準エラー経由）には付かない。
- 録音 1 回につき、開始・終了・長さ・転送量・最初の音声までの時間・最大音量が出る。
  **最大音量が 0 なら完全な無音**で、マイクの許可が下りていない可能性が高い（macOS は、許可の無いマイクに
  対してエラーではなく無音を返すことがある）。

gap: 録音要求を断ったこと（disarmed）は、裏で動いているあいだはログにしか出ない。利用者は、
文字が出ないという形でしか気づけない（計画中。[07](./07-roadmap.md)）。

## 5. 調査

### 5.1 `micmux doctor`（接続先）

アプリが仮想マイクに辿り着けるかを、順に点検する。

- 音声サーバーに接続できるか（必須）
- `pacat` があるか（必須）
- ALSA から音声サーバーへ繋ぐプラグインがあるか（警告）
- サウンドカードがあるか、または `arecord` があるか（警告）

### 5.2 `micmux debug [<host>]`（接続元）

状況をひとまとめに出力する。何も変更しない。マイクは合計で数秒だけ開く。

- micmux の版・実行ファイルの場所・OS
- 環境（ターミナルアプリ・シェル・tmux の内外・ssh-agent・PATH 上の micmux）
- 動いている client の状態とプロセス
- ログの末尾 40 行
- ssh の設定のうち関係する項目（`ssh -G` の出力から）
- 端末なしでの接続の可否と、接続先の `micmux doctor` の結果
- マイクから音が取れるか。**端末から直接の場合と、端末から切り離した場合の両方**

出力にはホスト名やユーザー名が含まれる。その旨を、出力の最後に表示する。

## 6. 開発と試験

- `cargo test` で単体テストを実行する（プロトコル・リサンプリング・録音ストリームの数え方・
  制御文字の除去・取得の停止など）。
- `scripts/e2e-linux.sh` で、音声の通しの試験を実行する。代役のマイク（音を流し込んだ null sink）から
  client が取得し、bridge を通って仮想マイクに届いた音を録って照合する。armed での転送、disarmed での拒否、接続先で鳴らした音が混ざらないこと（別の bridge が先に終わった場合と、既定の出力先を確かめられない場合を含む）、
  arm のし直し、client が突然終わったときの後片付けを見る。専用の音声サーバーを一時ディレクトリに立てる。
  `E2E_NATIVE=1` で、内蔵の取得（cpal → ALSA → PulseAudio）を通す。
- 接続先の音声サーバーを使う動作試験は、**利用者の実運用の音声サーバーとは別に立てた、隔離した
  インスタンス**で行う。手順と注意は `AGENTS.md` にある。
- 対応する Rust は 1.89 以降（`Cargo.toml` の `rust-version`）。
- `cfg(target_os = "macos")` の分岐は、Linux ではビルドできない。CI でも確かめない（§6.1）。
  変更したら、macOS の実機でビルドして確かめる。

### 6.1 CI

| workflow | 内容 |
|---|---|
| `ci` | ビルド・テスト・lint（警告は 0 件を保つ）、`native` feature の lint、`rust-version` の版でのビルド、音声の通しの試験。文書だけの変更では回さない |
| `audit` | 依存関係を、既知の脆弱性と照合する（`cargo audit`）。依存を変えた PR と、週に 1 回 |
| `secret-scan` | 全 ref の全履歴を、Betterleaks で秘密の検査にかける |

- **すべて Linux のランナーで回す。macOS のランナーは使わない**（決定）。macOS のランナーは、データセンターに
  並べた実機の Mac で動く資源であり、手元に接続元の Mac がある以上、そちらで確かめるほうが筋がよい。
  代わりに、macOS 向けの分岐のコンパイルエラーは、マージして利用者が更新するまでわからない。
- **通しの試験は、実機の無い側を補う。** 接続元を Linux にする場合の経路（内蔵の取得）と、bridge の
  音声サーバーを使う部分は、単体テストでは通らない。実際のマイクとそのドライバーの癖までは補えない。
- workflow の権限は読み取りだけにし、外部の Action は `actions/checkout`（コミットで固定）だけを使う。

### 6.2 秘密の検査

公開リポジトリなので、秘密を push の前と CI で止める（[README](./README.md)「公開リポジトリでの秘匿方針」）。

- 規則は `.betterleaks.toml`。組み込みの規則に、`.env*` をファイル名で止める規則を足している。
- push 前の検査は `.githooks/pre-push`。clone 後に `./.githooks/install.sh` を一度実行して有効にする。
- コミット時の検査は、ホストのグローバルな hook に任せ、リポジトリ側では持たない。
- 秘密の検査が拾うのは、トークンなどの形式の決まったものと `.env*` である。ホスト名やユーザー名のような
  **環境を特定する情報は拾えない**ので、書く側が気をつける。

gap: 書式（rustfmt）を統一していない（[#7](https://github.com/Daiius/micmux/issues/7)）。
