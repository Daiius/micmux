# 05. セキュリティとプライバシー

マイクは機微な資源である。誰が録音を始められるのか、何を信頼して何を信頼しないのかを定める。

---

## 1. 信頼の方針

**接続先を無条件には信頼しない。録音の最終決定権は接続元にある。**

SSH で通信が認証・暗号化されていても、接続先のサーバーや、そこで同じユーザー権限で動くプロセスが
信頼できるとは限らない。接続先からの録音要求は、あくまで要求として扱う。

| 相手 | マイクを起動できるか |
|---|---|
| ネットワーク上の第三者 | **できない。** 待ち受けポートが無く、入口が無い（§3.1） |
| 接続先の、別のユーザー | **できない。** 音声サーバーのソケットに届かない（§3.1） |
| 接続先で、利用者の権限を得た者 | **armed のあいだだけできる。** これを抑えるのが §2 |
| 接続元で、利用者の権限で動くプロセス | できる（arm できる）。**設計上の前提として許容する** |

3 行目は、接続先が乗っ取られている場合である。その時点で攻撃者は、利用者のシェル・ソースコード・
認証情報にも手が届いている。マイクはその延長にある追加の被害であって、micmux が新しく開けた入口ではない。
micmux が防ぐのは、**「接続先の乗っ取りが、接続元の部屋の盗聴にまで広がること」**である。

## 2. 録音の許可

### 2.1 armed / disarmed

- **起動直後は disarmed**（既定）。録音要求をすべて断る。
- `micmux arm` / `disarm` / `toggle`、または端末での Enter で切り替える。`--armed` を付けると、
  最初から許可した状態で始まる。
- 状態は保存しない。client が終われば消え、次に起動したときは既定に戻る。

**既定を armed にはしない**（決定）。公開しているツールなので、何も考えずに入れた人のマイクが
開く状態を避ける。

実際の使い方としては、自分専用の開発サーバーに対して `--armed` で常用し、拾われたくない場面でだけ
`micmux disarm` を打つ、という運用が現実的である。この場合、armed / disarmed は「止めるスイッチ」として
働く。armed のときの判定にコストは無い。

### 2.2 連続録音時間の上限

- 1 回の録音が `--max-seconds`（既定 120 秒）を超えたら、**録音を止めて disarm する**。
  続けるには `micmux arm` が要る。
- 録音中に START が届いて取得をやり直しても、時間は数え直さない。
- `--max-seconds 0` で上限を無効にできる。キーを押したまま考える使い方では、上限が邪魔になるため。
  無効にした場合、止める仕組みはキーを離すことと `micmux disarm` だけになる。

**上限は、1 回の録音の長さを抑えるだけである。** armed のあいだ、接続先が録音の終了と開始を繰り返せば、
上限より短い録音を何度でも始められる。録音の開始を接続先に委ねる仕組みである以上、これは避けられない。
録音させたくないあいだは disarm しておく。

### 2.3 気づく仕組み

防ぐ仕組みとは別に、OS のマイク使用中の表示がある（macOS ではメニューバーに出る）。
待機中はデバイスを開かないので、表示が出ているときは実際に録音している。

## 3. 攻撃面ごとの扱い

### 3.1 通信路

- **待ち受けポートを作らない。** client と bridge をつなぐのは SSH の標準入出力（プロセス間のパイプ）で、
  外から割り込む入口が無い。
- リバースフォワーディングを使わないのは、このためである。接続先の `localhost` にポートを開くと、
  同じサーバーの他の利用者が接続できてしまう（[01](./01-motivation.md) §3.3）。
- 接続先の音声サーバーの入口は、ユーザーごとのディレクトリ（`/run/user/<uid>`、他人は読めない）にある
  Unix ソケットだけである。

### 3.2 接続先から届くもの

接続先が悪意を持つ場合に、接続元で起こせることを抑える。

| 経路 | 扱い |
|---|---|
| 不正なフレーム | 長さを確保の前に確かめる。短すぎる payload や知らない type はエラーにする。panic しない |
| 想定外のメッセージ | 種類と長さだけをログに書く |
| `HelloAck` の source 名・`Error` | 制御文字を取り除き、300 文字で切る |
| 標準エラー（ssh と bridge のログ） | 制御文字を取り除く。1 行 300 文字・1 分 60 行・1 接続あたり 1 MiB まで |
| メッセージの連打 | 受け取っていない分を 64 件までに制限する。client 自身のログも 1 分 60 行まで |
| ログの肥大 | 起動時に 1 MB を超えていたら、1 世代だけ退避する |

- 接続先から届く値が、接続元のシェル・ファイルパス・コマンドの引数に流れる経路は無い。
- 制御文字を取り除くのは、端末の機能の悪用（タイトルの書き換え・クリップボードへの書き込み）を防ぐため。
  ただし接続先は、利用者の対話用の SSH を通じて同じ端末へ同じものを送れるので、上乗せされる能力は小さい。

gap: 接続先が受信を止めると、`disarm` も終了も効かなくなり、マイクが開いたままになる。止めた後の音声が
送られることはない（[#1](https://github.com/Daiius/micmux/issues/1)）。

### 3.3 接続元の、同じマシンの別のユーザー

- **操作用ソケット**: 権限は 0600。置き場所は `XDG_RUNTIME_DIR`、無ければ `TMPDIR`、macOS では
  ユーザーごとの一時ディレクトリ。どれも他人は触れない。
- **ログ**: ファイルは 0600、ディレクトリは 0700 で作る。symlink は辿らない。ログには、接続先のホスト名と
  録音の開始・終了の時刻が入る（いつ話していたかがわかる）ので、他人に読ませない。
  置き場所が決められない環境（`HOME` も `XDG_STATE_HOME` も無い）では、`/tmp` に書かずに起動を失敗させる。

gap: Linux の接続元で、`XDG_RUNTIME_DIR` も `TMPDIR` も無い場合は、ソケットを `/tmp` に置く。
別のユーザーに先回りされると、起動の妨害や状態の誤認が起こりうる
（[#2](https://github.com/Daiius/micmux/issues/2)）。

### 3.4 接続先の、同じマシンの別のユーザー

- 仮想マイクは、利用者ごとの音声サーバーの中にある。他人は録音要求を出せず、音声も聞けない。
- bridge が前の bridge を終わらせるとき、対象の pid は OS が返す値（ロックの持ち主）で、偽れない。
  他人のプロセスへのシグナルは、権限で失敗する。

gap: `XDG_RUNTIME_DIR` が無い接続先では、排他用のファイルを `/tmp` に置く。別のユーザーに先回りされると、
排他が効かなくなる（[#3](https://github.com/Daiius/micmux/issues/3)）。

### 3.5 引数

- `-` で始まるホスト名は拒否する。ssh へは `<host> -- <接続先のコマンド>` の順で渡す。
- sink の名前は、英数字と `_` `-` に限る（接続先のシェルに渡るため）。
- `--watch-pid` と `watch` の登録は、1 以下の pid を拒否する。
- `--capture-cmd` と `--transport` は `sh -c` で、`--remote-cmd` は接続先のシェルで実行される。
  これらは利用者自身が指定する値であり、コマンドとして解釈されるのは仕様である。

### 3.6 多重化を使う場合

`--mux`（[02](./02-architecture.md) §4.3）では、認証済みの接続を共有する。

- 端末で接続しているあいだと、最後の ssh を閉じてから `ControlPersist` の時間が経つまでは、
  接続元で利用者の権限で動くプロセスが、認証なしでその接続を借りられる。
- これは SSH の多重化そのものの性質で、認証を 1 回にすることと引き換えである。
- `ControlPersist` を短くすると、閉じたあとの時間だけが減る。

## 4. 残すもの・残さないもの

- 音声を保存しない。ログにも書かない。
- ログに書くのは、接続先のホスト名、録音の開始・終了の時刻、長さ、転送量、最初の音声までの時間、
  最大音量である。
- SSH の認証情報を、独自に保存・管理しない。

## 5. レビューの記録

2026-11-27〜28 に、コードレビュー・簡素化・セキュリティレビューを順に行った
（[decisions](./_grilling/decisions.md)）。セキュリティレビューでは、次のことを確認した。

- 重大な指摘は無い。接続先が悪意を持っていても、disarmed のまま録音させること、disarm した後の音声を
  送らせること、接続元でコマンドを実行させることはできない。
- 中程度の 2 件（上限のすり抜け・ディスクとメモリの消費）と、軽微な 4 件を修正した。
- 軽微な 3 件は、issue に記録して見送った（[#1](https://github.com/Daiius/micmux/issues/1)・
  [#2](https://github.com/Daiius/micmux/issues/2)・[#3](https://github.com/Daiius/micmux/issues/3)）。
- 依存関係は、すべて crates.io 由来で検査用の値が付いていることまでを確かめた。**既知の脆弱性との照合は
  していない**（[#7](https://github.com/Daiius/micmux/issues/7)）。
